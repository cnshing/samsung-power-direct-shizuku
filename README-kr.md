# Power Direct

삼성의 **우회충전**을 게임이 아닐 때도 유지한다.

*[English README](README.md)*

Galaxy 기기는 게임이 포그라운드에 있는 동안 배터리를 전류 경로에서 빼고 충전기가 시스템을
직접 먹인다. 배터리는 그동안 그냥 쉰다. 거치대에 꽂아 사는 태블릿에 이보다 나은 것은 없는데,
삼성은 이걸 게임에만 묶어뒀고 게임을 나가는 순간 사라진다.

이 앱은 포그라운드가 무엇이든 그 상태를 유지한다.

**Galaxy Tab S9+ (SM-X810) / Android 16 / One UI 8** 에서 끝에서 끝까지 검증했다.

---

## 먼저 읽을 것

공식 기능이 아니고, 마법 같은 배터리 절약 앱도 아니다. 설치하기 전에:

- **목표는 배터리 수명을 조금이라도 늘리는 것이지 충전을 완벽히 차단하는 게 아니다.**
  배터리가 전류 경로에서 빠지는 것이지 전기적으로 분리되는 게 아니다. 이 기기는 바이패스
  중 −16 mA 를 재지만, 다른 기기에서 30~70 mA 의 잔류 전류 보고가 있다.
- **펌웨어 쪽 조건은 그대로 살아 있고 우회 대상이 아니다.** 실제로 고속 충전을 협상한
  PD/PPS 충전기가 필요하고, **배터리 20% 이상**에서만 효과가 있다. 그 아래에서는 플래그가
  무시되고 정상 충전한다 — 그래서 방전으로 못 빠져나오는 상황은 생기지 않는다.
- **`Settings.System.pass_through` 는 삼성이 공개한 인터페이스가 아니다.** One UI 업데이트로
  예고 없이 바뀌거나 사라질 수 있다.
- **효과가 실제로 얼마나 되는지는 아무도 측정한 적이 없다.** 동작 원리는 검증됐지만
  장기적인 이득은 그렇지 않다.
- **shell 권한이 필요하고**, 그것을 자기 기기의 ADB 에서 빌린다. 즉 동작하는 동안 무선
  디버깅이 켜진다. [어떻게 동작하나](#어떻게-동작하나) 를 볼 것.
- 뭔가 이상해 보이면 복구 방법은 **재부팅**이다. `pass_through` 는 부팅마다 `0` 으로
  초기화되므로 앱을 지워도 기기가 스스로 원래대로 돌아온다.

## 무엇을 하나

충전기가 꽂혀 있는 동안, 100% 까지 채워 거기 눌러앉는 대신 잔량을 밴드 안에 붙잡아 둔다.

```
잔량 >= high   →  바이패스 켬   (충전기가 시스템에 직접 급전, 배터리는 쉼)
잔량 <  low    →  바이패스 끔   (정상 충전)
그 사이         →  현재 상태 유지  (히스테리시스, 플래핑 없음)
```

기본값 **low 65 / high 75**. 10%p 폭이면 플래핑이 없고, 65→75 충전은 약 13분이다.

`high` 기본값이 80 이 아니라 75 인 것은 의도적이다. 삼성 **배터리 보호**의 상한이 80 이고
그 값은 낮출 수 없어서, 우리도 80 에서 걸면 삼성 쪽이 먼저 작동해 80 에 걸어둔 채 트리클
충전을 한다. 그러면 우리가 하려는 일 — 배터리를 아예 전류 경로에서 빼는 것 — 이 일어나지
않는다. 그 아래에서 먼저 개입해야 진짜 바이패스가 걸린다.

충전기를 뽑으면 아무것도 하지 않는다.

### 모드

| 모드 | 동작 |
|---|---|
| **Auto** | 위의 밴드 정책 |
| **Always** | 잔량 무시하고 꽂혀 있으면 항상 바이패스 |
| **Off** | 바이패스하지 않는다. 정상 충전 |

### 표면

| | |
|---|---|
| **앱** | 모드, low/high 슬라이더, 실시간 잔량·전류·온도, 에이전트 상태, 활동 로그 |
| **퀵세팅 타일** | 탭 = Auto ↔ Off, 롱탭 = 앱 열기 |
| **홈 위젯** | 잔량·전류·상태·모드. 탭 = Auto ↔ Off |
| **알림** | 충전 중에만 표시 — 상태와 "지금 끄기" 액션 |

타일의 on/off 는 **사용자가 켜 둔 것이지 지금 일어나는 일이 아니다.** 자동 모드에서 잔량이
밴드 아래면 켜 둔 채로 정상 충전하는 것이 정상이다. 실제 상태는 부제(`Bypassing · 80%`)가
말한다.

## 설치

APK 를 설치한 뒤, 데스크탑에서 권한 하나를 준다. 앱이 자기에게 줄 수 없는 것이라 이것만은
불가피하다.

```sh
adb shell pm grant moe.qwreey.powerdirect android.permission.WRITE_SECURE_SETTINGS
```

앱을 열고 **Pair** 를 눌러 페어링을 한 번 마치면 그 뒤로는 스스로 한다. 재부팅 후 복구까지
사용자 개입이 필요 없다.

삼성 **배터리 보호**(설정 > 배터리, 80% 상한)를 같이 켜두면 좋다. 계층이 달라 충돌하지 않고
이중 안전장치가 된다.

**Android 11 이상**(그 전에는 무선 디버깅이 없다), arm64.

## 어떻게 동작하나

스위치는 `Settings.System.pass_through` (`0`/`1`) 다. `1` 이면 바이패스가 걸린다 — 8코어
포화 부하에서도 배터리 전류 0 으로 검증했다. 게임런처 등록도, 포그라운드 조건도 필요 없다.

쓰려면 **shell UID 가 필요하다.** `WRITE_SETTINGS` 로는 안 되고(AOSP 가 비공개
`Settings.System` 키 쓰기를 차단한다 — 권한 문제가 아니다), Shizuku 는 "Start on boot" 이
root 전용이라 탈락했다. 재부팅 후 복구가 필요한 바로 그 순간에 Shizuku 가 죽어 있다.

그래서 앱은 자기 기기에서 shell 을 빌린다.

```
앱  →(자체 ADB 클라이언트, 루프백, 부팅당 한 번)→  adbd  →  shell 에이전트
                                                              ↓
                                        Settings.System.pass_through
                                                              ↓
                                 BatteryService  →  sysfs pass_through
```

ADB 는 **부팅 후 한 번**, 작은 shell UID 에이전트를 띄우는 데에만 쓴다. 그 뒤로는 에이전트가
`dumpsys battery` 를 직접 읽으며 정책을 판단한다. 덕분에 앱이 백그라운드에서 깨어날 필요가
없다 — 알람도, 포그라운드 서비스도, 배터리 최적화를 꺼달라는 부탁도 없다.

ADB 구현(페어링, mDNS 탐색, TLS)은
[lan-mouse-android](https://github.com/qwreey/lan-mouse-android) 에서 이식했다.
