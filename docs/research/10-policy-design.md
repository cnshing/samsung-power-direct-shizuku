# 유지 정책 설계 — 그냥 1로 두면 안 되는 이유

## 문제

`pass_through=1` 을 상시 유지하면 배터리는 **단조 감소만 한다.**
꽂아도 안 차고, 뽑으면 줄어든다. 며칠이면 20%까지 내려가서 기능 자체가 무의미해진다.

## 해법 — 히스테리시스 밴드

목표는 "충전 금지"가 아니라 **"만충 근처에 오래 머무르지 않게 하는 것"** 이다.
리튬이온 수명은 고 SoC 체류 시간에 가장 민감하다.

```
충전기 연결 중:
    level <  LOW   →  pass_through = 0   (충전 허용)
    level >= HIGH  →  pass_through = 1   (바이패스)
    LOW <= level < HIGH  →  현재 상태 유지   ← 히스테리시스, 플래핑 방지

충전기 미연결:
    아무것도 하지 않는다 (pass_through 는 무의미)
```

**안전 바닥은 앱에 넣지 않아도 된다.** 실측 결과 **펌웨어가 20% 미만에서 이 플래그를 무시하고
정상 충전한다** (09 참조). 설정값은 1로 남지만 효과가 안 걸리므로 경합도 없다.
넣는다면 "불필요한 쓰기를 줄이는 최적화"이지 안전장치가 아니다.

기본값 제안: **LOW = 70, HIGH = 80**

- 밴드 폭 10%p면 플래핑이 사실상 안 생긴다
- 70→80 충전은 1009 mAh / 4.6 A ≈ **13분**. 하루 한두 번 도는 수준
- 80%는 삼성 **배터리 보호** 기본 임계값과 같다 (아래 시너지 참조)

사용자가 밴드를 조절할 수 있게 한다. 들고 다닐 일이 많으면 LOW/HIGH를 올리면 된다.

## 삼성 배터리 보호와의 시너지

`dumpsys battery` 에서 확인됨:

```
 mProtectBatteryMode: 0          ← 현재 꺼져 있음
 mProtectionThreshold: 80
 mMaximumProtectionThreshold: 80
```

삼성 자체 "배터리 보호"(80% 상한)를 **같이 켜두면 이중 안전장치**가 된다.
우리 앱이 죽거나 정책이 오작동해도 80% 위로는 안 간다.
둘은 다른 계층이라 충돌하지 않는다 — 보호는 상한, 바이패스는 경로.

## 트리거 수단 — 무엇을 쓸 수 있나

| 신호 | 매니페스트 등록 | 비고 |
|---|---|---|
| `ACTION_POWER_CONNECTED` / `_DISCONNECTED` | **가능** | Android 8+ 암시적 브로드캐스트 제한의 **면제 목록**에 있다. 앱이 안 떠 있어도 받는다 |
| `ACTION_BATTERY_CHANGED` | **불가** | 런타임 등록만 됨. 서비스가 살아 있어야 한다. 대신 잔량 변화마다 정확히 온다 |
| `ACTION_SCREEN_ON` | 가능 | **필요 없다.** 화면 껐다 켜기는 `pass_through` 에 영향이 없다 ([12](12-trigger-matrix.md)) |
| `ACTION_BATTERY_LOW` / `_OKAY` | 가능 | 임계값이 고정이라 밴드 제어엔 부적합 |
| `BatteryManager.getIntProperty(BATTERY_PROPERTY_CAPACITY / CURRENT_NOW)` | — | **권한 없이 아무 때나 읽기 가능.** 셸에서 막힌 전류를 앱은 본다 |
| `BOOT_COMPLETED` | 가능 | 재부팅 후 복구용 |

### 채택 구조

```
BOOT_COMPLETED          →  충전 중이면 정책 평가 (부팅 시 값이 초기화되므로)
ACTION_POWER_CONNECTED  →  포그라운드 서비스 시작
                              · BATTERY_CHANGED 런타임 등록
                              · 잔량 바뀔 때마다 정책 평가
                              · 알림에 현재 상태 + 전류 표시
ACTION_POWER_DISCONNECTED → 서비스 종료
```

**게임 세션 종료만이 유일한 외부 간섭이다** ([12](12-trigger-matrix.md)).
포그라운드 서비스가 살아 있는 동안에는 `BATTERY_CHANGED` 가 주기적으로 오므로
(잔량·전압·온도 변화마다) 그때 값을 확인해 재적용하면 자연히 복구된다.
게임 감지를 위해 `UsageStatsManager` 같은 걸 따로 붙일 필요가 없다.

**알림이 충전 중에만 뜬다** — 정확히 이 기능이 의미 있는 구간이다.
그리고 알림이 있다는 게 오히려 장점이다: 바이패스가 켜져 있다는 걸 사용자가 항상 알고,
거기서 바로 끌 수 있다. "왜 충전이 안 되지?" 사고를 막는다.

포그라운드 서비스가 싫으면 대안: `ACTION_POWER_CONNECTED` 에서 `AlarmManager` 로 5분 주기 평가.
다만 Doze 때문에 `setAndAllowWhileIdle` 은 최소 간격이 9분이라 밴드를 조금 넘길 수 있다.
70→80이 13분이니 실용상 문제는 없다.

## 수동 제어 — 위젯 / 퀵세팅 타일

`lan-mouse-android` 에 그대로 있는 것을 재사용한다:

```
app/src/main/java/moe/qwreey/lanmouse/AgentTileService.kt   퀵세팅 타일
app/src/main/java/moe/qwreey/lanmouse/AgentWidget.kt        홈 위젯
app/src/main/java/moe/qwreey/lanmouse/BootReceiver.kt       부팅 복구
```

세 가지 모드를 두면 충분하다:

| 모드 | 동작 |
|---|---|
| **자동** | 위 밴드 정책 |
| **강제 바이패스** | 잔량 무시하고 1 유지 (안전 바닥 25%는 그대로) |
| **끔** | 0 유지. 평소처럼 충전 |

타일 한 번 누르면 자동↔끔, 길게 누르면 강제. 위젯엔 현재 잔량·전류·모드 표시.

## 재부팅 시 초기화 — 설계에 반영

**실측 확인 (09 참조): 재부팅하면 `pass_through` 가 0으로 돌아간다.**
부팅 과정에서 시스템이 덮어쓴다.

두 가지가 따라온다:

### 1. `BOOT_COMPLETED` 리시버가 필수

부팅 후 정책을 다시 적용해야 한다. 다만 **충전 중일 때만** — 부팅 직후 충전기가 없으면
아무것도 하지 않고, 나중에 `ACTION_POWER_CONNECTED` 가 처리하게 둔다.

### 2. 위험이 크게 줄었다

`pass_through` 가 영속이었다면 "앱을 지웠는데 충전이 안 되는 태블릿"이 남았을 것이다.
이제는 **재부팅 한 번이면 자가 치유**된다.

그래도 사용자가 원인을 알 수 있어야 하므로 다음은 유지한다:

1. **알림 상시 표시** (충전 중) — 켜져 있음을 항상 알린다
2. 앱에 "끄고 나가기" 버튼 — 0으로 되돌리고 종료
3. 복구 안내를 앱/README에 명시:
   **"재부팅하면 원래대로 돌아옵니다"** (adb 명령보다 이쪽이 안내하기 쉽다)
   또는 `adb shell settings put system pass_through 0`
4. **펌웨어 바닥 20% 확인됨** (09) — 정책이 어긋나도 저전력에서 못 빠져나오는 일은 없다.
   20% 미만이면 플래그와 무관하게 정상 충전된다
